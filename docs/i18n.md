# Internationalisation

*Applies to `@intellectif/lk-react` 7.1.0 and later.*

The SDK renders two kinds of text, and they are not the same problem:

| | Whose words | Where the language comes from |
|---|---|---|
| **Authored content** — questions, options, passages, hints, feedback, rubric criteria | The author's | The content itself. `stimulus.locale` puts a `lang` on that passage; `locale` on activity **data** labels xAPI statements, not the DOM |
| **Chrome** — "Submit", "Question 3 of 10", "No plays remaining", the marking glyphs' announcements | The SDK's | `<LkIntlProvider>`, or a `strings` prop |

Before 7.1.0 the chrome was English literals, so a learner sitting a Spanish
paper read a Spanish passage inside an English scaffold, and a listening exam
could not say "No quedan reproducciones" at all. `<LkIntlProvider>` replaces
every one of those strings.

**The SDK ships the mechanism and English — no other bundled locale.** Shipping
Spanish, Portuguese or Arabic would mean shipping translations nobody in this
repository can review, and on a summative paper a wrong "No plays remaining" is
worse than an English one a teacher can see is untranslated. The words belong to
whoever speaks the language.

## Quick start

```tsx
import { LkIntlProvider } from '@intellectif/lk-react/i18n/LkIntlProvider';

<LkIntlProvider
  locale="es"
  strings={{
    submit: 'Enviar',
    checkAnswers: 'Comprobar respuestas',
    previous: 'Anterior',
    next: 'Siguiente',
    questionProgress: (index, total) => `Pregunta ${index} de ${total}`,
    wordCount: (n) => `${n} ${n === 1 ? 'palabra' : 'palabras'}`,
    media: { noPlaysRemaining: 'No quedan reproducciones' },
  }}
>
  <ActivitySequence activities={paper} />
</LkIntlProvider>;
```

Anything you omit keeps its English default, so a partial translation degrades
to mixed rather than to blank.

## Precedence

Later wins, key by key — a `media` or `stimulusKind` object is merged one level
deep rather than replaced, so overriding one label never blanks its siblings.

1. `DEFAULT_STRINGS` (English)
2. `<LkIntlProvider strings={…}>`
3. The component's own `strings` prop — `<MultipleChoice strings={{ submit: 'Entregar' }} />`
4. `mediaStrings` on a component, and `mediaBudget.strings` on `<ActivitySequence>` — both from 7.0.0, both still honoured, and both still the last word for the transport

A component without a provider above it renders the English defaults, so
`<MultipleChoice>` still works with no setup at all.

A second `<LkIntlProvider>` **replaces** the one above it rather than layering
onto it: it starts again from the English defaults, exactly as a nested
`<ThemeProvider>` starts again from `defaultTheme`. `locale` and `direction` do
not inherit from the outer provider either. To relabel one activity inside a
translated tree use that component's own `strings` prop, which does layer (step
3 above); to combine two provider levels deliberately, compose them yourself
with the exported `mergeStrings`:

```tsx
<LkIntlProvider strings={mergeStrings(spanish, sectionOverrides)}>…</LkIntlProvider>
```

There is a second `locale`, on the components. `<ActivitySequence locale>` and
each activity's `locale` prop put a `lang` on that component's own root, so they
should carry the same value you give the provider — the SDK's chrome renders
inside them. Authored content in a *different* language belongs on
`stimulus.locale`, which the stimulus panel puts on the passage alone.

## Interpolation and plurals are functions

There is no message format, no catalogue file and no runtime dependency. A
string that needs a value is a function:

```ts
questionProgress: (index, total) => `Pregunta ${index} de ${total}`,
wordCount: (n) => `${n} ${n === 1 ? 'palabra' : 'palabras'}`,
stimulusRange: (first, last) =>
  first === last ? `Pregunta ${first}` : `Preguntas ${first}–${last}`,
```

A format string like `"Question {n} of {total}"` needs a parser, and a parser
needs plural rules for every locale the SDK does not know. A function hands both
to you, who already have `Intl.PluralRules` and know your own language. It also
lets a translation reorder its arguments, which a positional token cannot, and
TypeScript checks the arity at the call site.

## Writing direction

`<LkIntlProvider>` renders a wrapper that carries `lang` and `dir` **only when
you supplied something that determines them**. With no `locale` and no explicit
`direction`, neither attribute is written, so an RTL host page keeps its own
direction instead of being flipped back to left-to-right by a provider that was
mounted only to translate text. `direction` defaults to `auto`, which derives
the direction from `locale`: `ar`, `arc`,
`dv`, `fa`, `he`, `ku`, `ps`, `sd`, `ug`, `ur` and `yi` are right-to-left, and
everything else is left-to-right. `directionForLocale()` is exported if you need
the same answer elsewhere, and `useLkDirection()` reports the direction in
force.

Set `direction` explicitly to override what the locale implies — for a locale
the SDK's list does not know, or to keep an English scaffold around
right-to-left content:

```tsx
<LkIntlProvider locale="ar" direction="ltr">…</LkIntlProvider>
```

`useLkDirection()` always reports a concrete `ltr` or `rtl` (it answers "which
way does this read", and falls back to `ltr`); it is only the DOM attribute that
is withheld when nothing declared one.

`skin.css` uses logical properties throughout, so the optional skin follows the
direction; this is verified by measured geometry in a real browser, not by
inspection. `defaults.css` sets no directional properties at all.

`lang` is set only when you pass a `locale`. Claiming `lang="en"` for a tree
nobody labelled would make a screen reader read a Spanish passage in an English
voice, which is worse than leaving it to the host document.

## What is NOT translated

- **Thrown errors.** Every `throw` in the package is addressed to the developer
  who wired the component up, not to the learner. Translating them would make
  them unsearchable and would put the one audience that can act on them behind a
  translation. They stay English.
- **Authored content.** Questions, options, hints, feedback, rubric criteria and
  `alt` text are yours; the SDK renders what you give it.
- **`unscorable` reasons.** These are developer-facing diagnostics. The
  component surfaces the *state* (`couldNotBeGraded`), which is translated, and
  leaves the reason on the element as `data-reason`.
- **Numbers and dates.** The SDK formats no dates. It renders three numbers: a
  whole percentage and a word count, both passed to a string you control, and
  the audio transport's `m:ss / m:ss` clock, which it formats itself. The clock
  is digits and punctuation — identical in English, Spanish and Portuguese — so
  it carries no key. The scrubber's *spoken* value does carry one
  (`media.timeValue`), because that one has a word in it.

## The full surface

50 keys. Every one is proven to reach the DOM by a test that overrides all of
them with sentinels and drives the real components — including every submitting
path in every render mode. Two things fail that test: a key no component reads
(by name), and an English default that survives a full override (which is what
catches a component keeping a hardcoded literal).

### Submission

| Key | English default | Where |
|---|---|---|
| `submit` | `Submit` | Multiple Choice, Written Response |
| `checkAnswers` | `Check answers` | Fill in the Blanks, `practice` |
| `submitAnswers` | `Submit answers` | Fill in the Blanks, `exam` |

### Outcome

| Key | English default | Where |
|---|---|---|
| `scoreAnnouncement(percent, passed)` | `Score 82%. Passed.` | All three activities |
| `answerSubmitted` | `Answer submitted.` | Announced on submit, before the score |
| `notGradedYet` | `Not graded yet.` | A `deferred` outcome — never rendered as 0% |
| `noGradeAvailable` | `No grade available.` | An `unscorable` outcome |

`percent` arrives already rounded. Authored overall feedback is appended
separately by the component, so a translation of this sentence never has to
carry the author's words.

### Written Response

| Key | English default | Where |
|---|---|---|
| `responseSubmitted` | `Response submitted. It will be graded and your result will appear here later.` | Announced on hand-in. Distinct from `awaitingGrade`, which is the `review`-mode state of a submission made earlier |

### Shared stimulus

| Key | English default | Where |
|---|---|---|
| `stimulusKind.text` | `Passage` | Accessible name of an untitled stimulus region |
| `stimulusKind.audio` | `Recording` | |
| `stimulusKind.video` | `Video` | |
| `stimulusKind.image` | `Image` | |
| `stimulusKind.mixed` | `Material` | |
| `stimulusRange(first, last)` | `Questions 3–8` | Called with equal `first` and `last` for a single question, so a translation picks its own singular |

`stimulusKind` is keyed by kind rather than being one word, because "Recording"
and "Passage" do not share a gender or an article in every language.

### Embedded media

| Key | English default | Where |
|---|---|---|
| `embeddedMedia` | `Embedded media` | Accessible name of a provider iframe whose author supplied no `alt`. `MediaSchema` requires `alt` on an embed, so validated content never reaches it — but `validateActivity` is opt-in |

## Exports

From `@intellectif/lk-react` (barrel) and `@intellectif/lk-react/i18n/LkIntlProvider`:

| Export | What it is |
|---|---|
| `LkIntlProvider` | The provider: `strings`, `locale`, `direction` |
| `useLkStrings(override?)` | The strings in force, with an optional per-component override on top |
| `useLkDirection()` | `'ltr'` or `'rtl'` |
| `directionForLocale(locale)` | BCP 47 tag → direction |
| `DEFAULT_STRINGS` | The English dictionary — a useful base for a translation |
| `mergeStrings(base, override)` | The two-level merge the provider uses |
| `LkStrings`, `LkStringsOverride`, `LkDirection`, `LkIntlProviderProps` | Types |
